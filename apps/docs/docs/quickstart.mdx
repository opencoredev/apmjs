title: Quick start
description: Point bun, npm or pnpm at apm, then add a package with the apm CLI.
---

By the end of this page your package manager installs through apm, and `apm add` checks a package before it installs it.

The registry is `https://registry.apmjs.dev/`. It serves every npm package, and adds a score, yank and revoke on top.

## 1. Point your package manager at apm

Pick your package manager. Each setting goes in the project folder, so it applies to that project only.

<Tabs>
  <Tab title="Bun">
    Add this to `bunfig.toml`. The scanner makes plain `bun install` refuse revoked and confirmed-malicious versions, and warn about versions scoring under 40 (`APM_SCANNER_STRICT=1` refuses those too).

    ```toml title="bunfig.toml"
    [install]
    registry = "https://registry.apmjs.dev/"

    [install.security]
    scanner = "@apm/bun-scanner"
    ```

    The scanner is not on a registry yet. Until it is, install it from a clone of apm; see [Bun scanner](/guides/bun-scanner#install-it). Without it, the `registry` line alone still works.
  </Tab>
  <Tab title="npm">
    Add this to `.npmrc`. The `~safe` view hides versions under 24 hours old and versions scoring under 40.

    ```ini title=".npmrc"
    registry=https://registry.apmjs.dev/~safe/
    ```
  </Tab>
  <Tab title="pnpm">
    pnpm reads the same `.npmrc` as npm.

    ```ini title=".npmrc"
    registry=https://registry.apmjs.dev/~safe/
    ```
  </Tab>
</Tabs>

Then install as usual (`bun install`, `npm install`, `pnpm install`). Packages come from apm, which fetches them from npm, checks each tarball against npm's checksum and scores it.

:::tip
For npm and pnpm, the plain registry URL (without `~safe/`) serves every version npm has. Use it when you only want `apm add` to apply the checks.
:::

## 2. Get the apm CLI

`apm` is not on a registry yet. Run it from a clone. You need Bun 1.4 or newer.

```bash
git clone https://github.com/opencoredev/apmjs.git
cd apmjs && bun install
alias apm="bun $PWD/packages/cli/src/main.ts"
apm --version
```

`apm --version` prints `0.1.0`. Put the `alias` line in your shell profile to keep it.

apm uses the package manager your project already uses: it reads the lockfile, then the `packageManager` field in `package.json`, then falls back to bun when bun is installed and npm when it is not. Pass `--pm npm` to choose.

## 3. Add a package

```bash
apm add zod
```

apm asks the registry for the newest version that is at least 24 hours old and not revoked, yanked or confirmed malicious, prints its score card, and checks every package under it. Then it runs your package manager with the exact version, holds back install scripts until it has compared every installed package with what the registry served, and runs the scripts last.

```text
✓ zod@4.6.7  score 90/100 (A)
   -10 eval  Evaluates code built at runtime (eval, Function, vm)
        v4/core/compile.js:184: const factory = new F(...constantNames, factoryCode);
```

A score informs; it does not block. If the package or one it brings in scores under 40, was not fully analysed, has no score, or could not be looked up, apm prints a warning with the score, the top reasons (file and line) and a link, then installs. Run `apm add --strict` (or set `APM_STRICT=1`) to refuse those instead.

If a package is refused, apm says why and whether `--force` would help. `--force` lifts the cooldown for the named package only, and in strict mode its score floor. Revoked and yanked versions, and versions apm reviewers confirmed malicious, stay blocked.
