By the end of this page your package manager installs through apm, and `apm add` checks a package before it installs it.

The registry is `https://registry.apmjs.dev/`. It serves every npm package, and adds a score, yank and revoke on top.

## 1. Point your package manager at apm

Pick your package manager. Each setting goes in the project folder, so it applies to that project only.

<Tabs>
  <Tab title="Bun">
    Add this to `bunfig.toml`. The scanner makes plain `bun install` refuse revoked and confirmed-malicious versions, and warn about versions scoring under 40 (`APM_SCANNER_STRICT=1` refuses those too).

    ```toml title="bunfig.toml"
    [install]
    registry = "https://registry.apmjs.dev/"

    [install.security]
    scanner = "@apm/bun-scanner"
    ```

    The scanner is not on a registry yet. Until it is, install it from a clone of apm; see [Bun scanner](/guides/bun-scanner#install-it). Without it, the `registry` line alone still works.
  </Tab>
  <Tab title="npm">
    Add this to `.npmrc`. npm then installs through apm: new installs skip revoked, yanked and confirmed-malicious versions, and the tarballs of revoked and confirmed-malicious versions answer 410 even to an existing lockfile.

    ```ini title=".npmrc"
    registry=https://registry.apmjs.dev/
    ```
  </Tab>
  <Tab title="pnpm">
    pnpm reads the same `.npmrc` as npm.

    ```ini title=".npmrc"
    registry=https://registry.apmjs.dev/
    ```
  </Tab>
</Tabs>

Then install as usual (`bun install`, `npm install`, `pnpm install`). Packages come from apm, which fetches them from npm, checks each tarball against npm's checksum and scores it.

apm's package documents leave out fields npm's have and no install reads from them: each version keeps its install fields, scripts, links and checksums, and drops the rest (`licenseText`, `readme`, the `exports` map, npm's signatures), and the abbreviated form installs use has no `devDependencies`. `npm view <package> devDependencies` still works. The full list is in [What apm's packuments leave out](/reference/http-api#what-apms-packuments-leave-out).

:::tip
For a strict mode with stock npm or pnpm, use `registry=https://registry.apmjs.dev/~safe/` instead. The [`~safe` view](/guides/safe-view) hides versions under 24 hours old, versions scoring under 40 and versions apm has not fully analysed, so some large packages have no version it can install.
:::

## 2. Get the apm CLI

Install it with one command. The install script downloads one prebuilt binary for macOS or Linux (x64 or arm64, and musl systems such as Alpine on x64). Running it needs no git, Bun or Node.

<Tabs>
  <Tab title="Install script">
    ```bash
    curl -fsSL https://apmjs.dev/install | sh
    ```
  </Tab>
  <Tab title="Homebrew">
    On macOS or Linux with Homebrew:

    ```bash
    brew install opencoredev/tap/apm
    ```
  </Tab>
</Tabs>

The rest of this section describes the install script.

The script installs to `~/.apm/bin/apm`, never uses sudo and does not edit your shell profile. It prints the line to add to your PATH instead:

```bash
export PATH="$HOME/.apm/bin:$PATH"
apm --version
```

`apm --version` prints `0.1.3`. To update, run the install command again. To uninstall, delete `~/.apm`.

### What the install script checks

When a version is released, the SHA-256 of each of its binaries is written into the script. The script downloads the binary for your machine from `https://apmjs.dev/cli/<version>/`, compares its SHA-256 with that list, and installs nothing if they differ. It also runs the binary once and installs it only if it reports that version. It prints the fingerprint it checked:

```
apm 0.1.3 (darwin-arm64) installed to /Users/you/.apm/bin/apm
SHA-256 <64-char hex digest>, checked against this script
```

To read the script before it runs, save it first:

```bash
curl -fsSL https://apmjs.dev/install -o install.sh
less install.sh
sh install.sh
```

### In scripts and agents

`curl | sh` suits a person who reads what it prints. A script or an agent that runs apm next must not carry on after a failed install with an apm left from before. Save the script to a temporary folder, run it only if it arrived whole, pin where it installs, and run apm only if the install succeeded:

```bash
APM_DIR="$(mktemp -d)" &&
  APM_SCRIPT="$APM_DIR/install.sh" &&
  curl -fsSL https://apmjs.dev/install -o "$APM_SCRIPT" &&
  tail -n 1 "$APM_SCRIPT" | grep -Fqx 'main "$@"' &&
  APM_OUT="$(APM_INSTALL="$HOME/.apm" sh "$APM_SCRIPT")" &&
  printf '%s\n' "$APM_OUT" &&
  printf '%s\n' "$APM_OUT" | grep -q '^SHA-256 [0-9a-f]\{64\}, checked against this script$' &&
  "$HOME/.apm/bin/apm" --version
```

The script's last line is the call that runs it, so an empty or cut-off download fails the `tail` check instead of exiting 0 with nothing installed, and apm runs only when the install printed the SHA-256 it checked. This is what the prompt on `https://apmjs.dev/publish` gives agents.

To check a binary by hand, compare its SHA-256 with the line for your platform in the script and in the version's published checksums:

```bash
curl -fsSL https://apmjs.dev/cli/0.1.3/SHA256SUMS
shasum -a 256 ~/.apm/bin/apm     # sha256sum on Linux
```

The script, the checksums and the binaries all come from apmjs.dev. The check proves the binary is the one released with the script you read; it does not prove who released it.

`--version X` or `APM_VERSION=X` installs another released version: `curl -fsSL https://apmjs.dev/install | sh -s -- --version 0.1.3`. `APM_INSTALL=<dir>` installs to `<dir>/bin/apm`. Windows is not supported yet. On Alpine, apm needs `libstdc++` and `libgcc` (`apk add libstdc++ libgcc`).

apm uses the package manager your project already uses: it reads the lockfile, then the `packageManager` field in `package.json`, then falls back to bun when bun is installed and npm when it is not. Pass `--pm npm` to choose.

## 3. Add a package

```bash
apm add zod
```

apm asks the registry for the newest version that is at least 24 hours old and not revoked, yanked or confirmed malicious, prints its score card, and checks every package under it. Then your package manager computes the add's lockfile in a copy of your project, installing nothing, and apm checks every package in it at its exact version. Only a lockfile that passes is written to your project and installed, with install scripts held back until apm has confirmed the install matches it. A revoked or yanked version anywhere in that lockfile refuses the add before anything in your project changes.

```text
✓ zod@4.6.7  score 90/100 (A)
   -10 eval  Evaluates code built at runtime (eval, Function, vm)
        v4/core/compile.js:184: const factory = new F(...constantNames, factoryCode);
```

A score informs; it does not block. If the package or one it brings in scores under 40, was not fully analysed, has no score, or could not be looked up, apm prints a warning with the score, the top reasons (file and line) and a link, then installs. Run `apm add --strict` (or set `APM_STRICT=1`) to refuse those instead.

If a package is refused, apm says why and whether `--force` would help. A package or dependency published in the last 24 hours installs with a warning; `--strict` refuses it. `--force` lifts the cooldown for the named package only, and in strict mode its score floor. Revoked and yanked versions, and versions apm reviewers confirmed malicious, stay blocked.
