---
title: Bun scanner
description: Make stock bun install and bun add ask apm about every package, and cancel the install on revoked or low-scoring versions. Strict mode for CI.
---

`@apm/bun-scanner` plugs into Bun's security scanner hook. Before `bun install` or `bun add` installs anything, Bun hands the scanner the package list, the scanner asks the apm registry about each package, and Bun cancels the install when a version is:

- revoked, or waiting to be revoked;
- scored below 40;
- still being analysed after the scanner has waited 60 s for it.

You keep using plain `bun`. No wrapper, no alias.

## Install it

:::note
`@apm/bun-scanner` is not published to a registry yet. Until it is, install it from a clone of apm as a file dependency. See the [limit this causes in strict mode](#strict-mode-for-ci).
:::

```bash
git clone https://github.com/opencoredev/apmjs.git ~/src/apmjs
bun add -d ~/src/apmjs/packages/bun-scanner
```

Bun needs the scanner in the project's own dependencies; a global install is not enough.

Then point Bun at apm and turn the scanner on:

```toml title="bunfig.toml"
[install]
registry = "https://registry.apmjs.dev/"

[install.security]
scanner = "@apm/bun-scanner"
```

Run `bun install`. A refused install stops with the package, the version and the reason.

## Which registry it asks

The scanner asks exactly one registry:

1. `APM_REGISTRY`, when it is set;
2. otherwise `[install] registry` from `bunfig.toml`, the project's first, then your global one.

It never takes a registry from package data, so a tarball URL in a lockfile cannot choose who checks it or who sees your package list.

## Versions still being analysed

A version nobody has scored yet is queued for analysis. The scanner treats it as pending, never as clean: it asks again every few seconds for up to 60 s, printing which packages it is waiting for. A cold package usually gets its score in a few seconds, and the install then goes ahead or is cancelled on that score. Anything still pending after 60 s cancels the install, in default mode and in strict mode:

```text
apm scanner: waiting for 1 package(s) the registry is still analysing (0s of 60s): left-pad@1.3.0
error: left-pad@1.3.0 is still being analysed by https://registry.apmjs.dev/ (waited 60s). apm installs no version before it has a score; try again in a minute.
```

Run the install again a minute later. Set `APM_SCANNER_WAIT_MS` to wait longer or shorter.

The scanner blocks every pending version, not only ones new to the registry: it cannot tell a long-published package nobody has installed through apm from one published a minute ago, and both have no score.

Some versions never get a score: a tarball too large to download or unpack, one the upstream serves in no form apm can check, one apm cannot read, or one whose analysis keeps running past the registry's limits. The registry answers each with a `fatal` advisory naming the reason, so the install is cancelled in default mode and in strict mode, including when the version was pending at first and its analysis ended that way while the scanner waited.

## What it cannot check

The scanner prints one warning per package it could not check:

- no registry is configured;
- the registry is unreachable, or is not an apm registry;
- Bun downloads the package from a different host than the configured registry;
- the version is a git, file or link dependency, which no registry serves.

By default those installs go ahead, so a registry outage does not stop your work. Prereleases (`1.0.0-beta.1`) are checked like any other version.

## Strict mode for CI

In CI, set `APM_SCANNER_STRICT=1`. Any package the scanner could not check then cancels the install:

```bash
APM_SCANNER_STRICT=1 bun install --frozen-lockfile
```

```text
apm scanner: not checked: my-tool@file:../my-tool: not a registry version (git, file or link dependency), so no registry can check it
error: Security scanner failed: apm scanner: 1 package(s) not checked and APM_SCANNER_STRICT=1, so the install is cancelled
```

:::warning
While the scanner itself is installed from a path, strict mode reports it as a file dependency it cannot check, and cancels every install. Strict mode becomes usable once `@apm/bun-scanner` is on the registry. Until then, use strict mode only in projects that list no git, file or link dependencies, which rules out this way of installing the scanner.
:::
